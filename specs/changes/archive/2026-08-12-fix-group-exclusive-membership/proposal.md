# Server-Authoritative Exclusive Group Membership

## Problem

**Termyard layout groups** (tiled pane groupings saved to `groups.json` on disk/backend and synced to clients via `/api/groups` and WebSocket) currently have no exclusive membership enforcement at the backend. A session key can appear as a leaf in multiple groups simultaneously, leading to:

1. **Membership ambiguity:** A tiled session moved into group B still exists in group A (no removal from A). User sees stale layout in A; killing or hiding the session does not clean up all references.
2. **Dead-session ghosts:** When a session dies (owner host offline, session killed), orphaned leaf nodes remain in group trees indefinitely. Groups may display "Waiting for session X" forever, or the UI crashes when trying to render a dead session.
3. **Corruption on peer divergence:** Two peers may apply group-tree edits in different orders, resulting in a session appearing in multiple groups on one peer and only one group on another. Last-write-wins timestamps cannot repair this because the writes themselves are ambiguous (which group should win?).
4. **Naming coordinator ghost entries:** Groups with modified membership can leave UNNAMED (auto-named) entries that never resolve if the group's enforcement changes, leaving placeholder group names in the sidebar.

## Desired outcome

All group trees are server-authoritative: after any write (SetTree, ApplyRemote, ApplySnapshot, MigrateKey), a session key is an exclusive leaf in at most one **live** group — the most-recently-written group wins, all other groups' references to that key are pruned immediately. Groups with insufficient leaves are tombstoned (removal records persisted, not deleted from disk). Stale peer deltas never resurrect tombstoned groups. Client pushes are guarded against passive divergence (only user-initiated edits, never group-switch or snapshot-reconcile). Dead sessions are opportunistically cleaned from group trees on GET /api/groups, healing persistent corruption.

## Scope

1. **Exclusive membership enforcement.** New internal method `enforce(now, winnerID)` in `pkg/groupsync` replaces `dedupeLiveGroups` and runs on every write path (SetTree, ApplyRemote, ApplySnapshot, MigrateKey). For each session key, if it appears in >1 live group, delete all but the most-recently-touched group (timestamp-based or `winnerID` if provided). Groups falling below 2 leaves are tombstoned (their record marked deleted with updated timestamp, persisted, but not removed from `groups.json`).

2. **Server-side dead-session pruning.** New exported method `Reconcile(gone func(key) bool)` in `pkg/groupsync` takes a callback returning true if a session is provably dead (owner host online, session not in `/api/sessions`). Runs on GET `/api/groups` to proactively remove leaf nodes for dead sessions, healing stale group state. Tombstoned entries are pruned opportunistically too, freeing disk space over time.

3. **No LWW resurrection of tombstoned groups.** Peer tree deltas (remote ApplyRemote) never resurrect a tombstoned group — if a delta adds members to a group whose record shows it deleted, the delta is discarded for that group. Prunes and tombstones bump their timestamps, ensuring LWW converges correctly.

4. **Client push gating.** Frontend only pushes trees on user-initiated edits (split/close/resize/drag/pair). Group switch or passive divergence reconciliation (snapshot mismatch) do not trigger pushes. Track via `paneTreeRev` pushed on PUT, prevent push during `skipTreeAdoptFor` guard (reconciliation window). This stops clients from amplifying server-authoritative enforcement back to other peers as their own edits.

5. **Enforcement-driven naming cleanup.** When a group's membership changes via enforcement, notify naming coordinator via `ObserveTreeMutation(treeID, newMemberSet)` and `Cancel(treeID)` to detect and scrub UNNAMED ghosts (placeholder names that never resolved). Prevents groups with enforced membership changes from lingering with autogenerated names.

6. **Snapshot reconciliation as server-authoritative.** `groups/snapshot` replaces client group map and immediately reconciles the active group's local pane tree (pane additions only, never prunes) unless a local edit is currently in flight (`paneTreeRev` > server version). This ensures the server's exclusive membership is the single source of truth, and clients converge by adoption, not by their own editing.

7. **Targeted documentation.** Update `docs/ux-contracts.md` section 2.1a to document server-enforced dissolution and exclusive membership, and add a dedicated "groups sync & exclusive membership" contract near the backgrounding section to describe enforcement, dead-session healing, and naming behavior.

## Non-goals

- Changing group tree structure or keys (`/api/groups` endpoint shape, group ID/name/rank fields).
- Changing the dissolution threshold (still 2 leaves minimum before tombstone).
- Changing the naming/AI-naming service; only notify it of enforcement-driven changes.
- Replicating server enforcement on the client; client-side adoption of server truth is sufficient.
- Modifying daemon/session lifecycle; sessions die as they do today; healing is opportunistic, not proactive.

## Risks

- `Reconcile` coroutine during GET /api/groups may briefly block group fetches if the gone-session callback is slow (e.g. during a peer sync hiccup). Mitigated: callback is local in-memory check, not I/O.
- Pushing `ObserveTreeMutation` to naming coordinator may fire redundantly if a group is enforced multiple times in one request (same session pruned from multiple groups). Mitigated: naming coordinator is idempotent; calling it many times per group ID is safe.
- Stale peer deltas crossing the network after a tombstone is created may not resurrect the group, but may cause the receiving peer to mark it unreachable. Mitigated: documented in ux-contracts as a known LWW edge case; users are protected by server-authoritative snapshot on next reconnect.
- Dead-session pruning is opportunistic (not guaranteed) until the client next calls GET /api/groups. Peers in isolated partitions may linger with dead-session leaves. Mitigated: clear in ux-contracts; healing is best-effort.

## Acceptance criteria

1. A session moved from group A to group B (via drag or split) is **removed from A, added to B, never in both**.
2. Killing a session removes its leaf from all groups immediately (via `onSessionRemoved` broadcast or removal detected in Reconcile).
3. A group is tombstoned (record marked deleted, timestamp bumped) when it falls below 2 leaves; no group ever has exactly 1 leaf in a live tree.
4. A stale group tree on disk with dead-session leaves has those leaves pruned on GET /api/groups, and the healed tree is returned to the client.
5. Peer tree deltas arriving after a group is tombstoned do not resurrect the group; the tombstone timestamp ensures LWW skips the stale delta.
6. A client in the middle of a local pane-tree edit (split/drag/close) does not push that tree to the server until the edit is complete; snapshot reconcile does not cause a client push.
7. When a group's membership is enforced (exclusive winner chosen), the naming coordinator is notified and can clean up UNNAMED placeholder names.
8. Group sync contract in ux-contracts documents exclusive membership, dead-session pruning, and naming behavior, with verification pointers to pkg/groupsync and web/src/state/workspaceReducer.ts.
