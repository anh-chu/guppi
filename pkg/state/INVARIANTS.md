# Lean v2 state invariants

This document freezes the contracts implemented by `pkg/state/ids.go`,
`document.go`, `invariants.go`, and `policy.go`. It is a design-freeze artifact;
runtime behavior remains behind existing code paths.

## Identity

- `OwnerID`, `SessionID`, `LayoutID`, `SplitID`, and `CommandID` are opaque
  base32 strings. They are generated by `crypto/rand` and validated by the
  following rules:
  - non-empty;
  - length at most 64;
  - ASCII lowercase alphanumerics only;
  - no `/` or `\\` path separators.
- No canonical identity field is derived from a mutable display label or name.
- `SessionRef` is the canonical pane identity. String form:
  - local:  `"<session>:<window>.<pane>"`
  - remote: `"<owner>/<session>:<window>.<pane>"`
  It is used as a map key, in URLs, and in JSON.

## State document

- `AppDocument.Schema` must be exactly `3`. Schema values greater than `3` are
  rejected as unknown future versions; values less than `3` are unsupported.
- One `AppDocument` owns the catalog and layouts for exactly one `OwnerID`.
- `LocalSessionRecord.ID` is stable for the lifetime of the session and is not
  changed by renaming.
- Mutable display data (`Name`, `DisplayName`, `ProjectPath`, etc.) lives in
  `_compat` structs, never in canonical identity fields.
- No canonical type contains wall-clock last-write-wins fields. Concurrency is
  governed by integer revisions and commands, not timestamps.

## Pane tree

- A pane tree is a binary tree of `PaneNode` values. Every node is either a
  `leaf` with a `SessionRef` or a `split` with a direction, ratio, and two
  children.
- Split ratios are finite floats in the open interval `(0, 1)`.
- Split direction must be `"h"` (horizontal) or `"v"` (vertical).
- A split must have exactly two non-nil children.
- No leaf `SessionRef` may appear more than once in the same tree.

## Layouts and workspaces

- `LayoutRecord` is a named, persisted layout. `WorkspaceRecord` is the active
  workspace for an owner.
- A workspace `ID` must also exist in the document's `Layouts` list.
- Layout IDs and `Order` values must each be unique within an `AppDocument`.
- Session membership is exclusive across all layouts and workspaces for an
  owner: a session reference may appear as a leaf in at most one layout or
  workspace. `CheckSessionMembershipAcrossLayouts` enforces this.

## Revisions and snapshots

- `AppDocument.Revision` is the persisted owner-scope catalog revision.
- `WorkspaceRecord.Revision` and `LayoutRecord.Revision` are owner-scope
  persisted revisions for layout state.

- The first snapshot on a new transport generation is accepted unconditionally.
  Subsequent snapshots are accepted only when their transport generation
  matches the current one.

## Commands

- `CreateIntent` carries an idempotent creation request. `CommandReceipt`
  acknowledges acceptance and exposes a monotonic `Seq`.
- Receipts older than `MaxCommandReceiptAge` are rejected.
- An owner may not accumulate more than `MaxPendingCommands` live receipts.
- Create retries use the policy constants in `policy.go`:
  - initial delay `CreateRetryInitial`;
  - max delay `CreateRetryMax`;
  - max attempts `MaxCreateRetries`;
  - unconfirmed intent cap `MaxPendingCreates`.

## Errors

- Invariant failures are returned as `StateError` with stable `ErrorCode`
  values (`ErrDuplicateIdentity`, `ErrMalformedSplit`, etc.). Runtime code
  should switch on these codes, not on string messages.
